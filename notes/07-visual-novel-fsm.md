# 视觉小说也是状态机：为什么先做这一幕 HTML

前四站都在地下城里教同一件事：生成、视野、主持人、对话、记忆，都必须是约束表。你真正想出货的体裁，却是视觉小说——左侧立绘、右侧选项、没有走路。

这一课只证明一件事：**表不是 Roguelike 的特殊技巧。** 灰岩从格子里的小人站起来，变成一幕对话。状态还是 `问候 → 打听 / 交易 / 警告 → 告别`。旗标还是四个。模型仍然只写 2～3 句。换油仍然按表回血。你没有重写故事，你只换了壳。

## 视觉小说为什么也是状态机

玩家眼里的视觉小说，是「一个人站在那里说话，我点按钮」。机器眼里，它和地牢对话是同一种东西：

| 玩家看见的 | 机器在做的 |
|---|---|
| 这一幕他肯说什么 | 当前状态列出的选项 |
| 点了之后他去哪一幕 | 表上的 `next` |
| 换了油、听过警告 | 旗标 `traded` / `warned` |
| 他说的那几句话 | LLM 只负责口气 |

自由聊天看起来更「像人」。问题完全没变：对方一旦能说任何话，也就能答应任何事。「我带你出城」「你的生命变成 999」。句子好听，游戏碎了。视觉小说比 Roguelike 更依赖这句话——整晚都在点选项。如果选项不能跳到表外的状态，故事才是你写的；否则故事是模型联想出来的。

所以：**角色是一张表，立绘是皮肤。** 地牢用格子当皮肤，这一幕用剪影当皮肤。皮肤可以换，表不能抄第二份。

## 这一幕 HTML 是通往 Godot / Ren'Py 的桥

现在还不要装引擎。理由很具体：

1. 你刚见过端口和账本。立刻再装 Godot 或 Ren'Py，会把「打开就能懂」打断第二次。编辑器、场景树、脚本语言，每一项都是新名词。
2. 若第一课 Godot 是对着空白窗口从零搭项目，你会以为「做游戏 = 学软件」。这一幕先让你摸到：**要搬的是表，不是故事。**
3. `vn.html` 双击就能玩。立绘是几何剪影，没有图片资源。选项按钮就是状态机的边。HP 条还在——交易写着治疗 3 点，开局 7 点，换油后应看到 7→10。句子可以写暖意，数字不归模型。

以后装 Godot 4 或 Ren'Py，你做的第一件事不是「重新写灰岩」，而是：

- 把 `js/npc-table.js` 里的 `TABLE` 变成 Godot 的 Dictionary，或 Ren'Py 的 `label` 跳转表；
- 立绘换成精灵或分层图；
- 选项按钮换成引擎自带的 UI；
- LLM 适配器和账本可以暂时仍用现在这套，也可以以后再搬。

故事（状态、选项、后果、旗标）已经在表里。引擎只是另一层皮肤。

## 两壳共一表，不要叉开

| 谁 | 决定什么 | 不决定什么 |
|---|---|---|
| `js/npc-table.js` | 状态、选项、下一跳、残页换哪件物品、回几滴血、本地台词库 | 怎么画、在不在格子里 |
| 地牢壳 `js/npc.js` | 落在哪一格、走近才开口、警告在地图上标一处异兆 | 另一套状态 |
| 视觉小说壳 `js/vn.js` | 立绘、对话框、没有走路；警告只立旗标（没有格子可标） | 另一套状态 |
| LLM | 当前状态怎么把那一跳说出口 | HP、物品、下一站 |
| 账本 | 这条测线上发生过哪几件事实 | 聊天记录 |

测线默认仍是 `stardust-7`。账本开着时，地牢里换过油，这一幕也不会再换——同一个人，不是两个副本。账本没开，他失忆，这一幕照常可玩。

想自己拧：打开 `js/npc-table.js`，只改交易的治疗点数，或把问候里某一跳的 `next` 改掉。保存，分别打开 `index.html` 和 `vn.html`。你会立刻感到：改的是规则，两处皮肤一起变。如果只改 `vn.js` 里的句子，表没动，他仍不会从问候跳到告别。

Demo 6 才适合打开 Godot：那时你手里已经有一张证明过的表，第一间房不会是空的。
